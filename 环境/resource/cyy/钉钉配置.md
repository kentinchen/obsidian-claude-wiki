## 一、钉钉开放平台配置

### Step 1：创建企业内部应用

1. 登录 [钉钉开发者后台](https://open-dev.dingtalk.com/)
2. **应用开发** → **自定义应用** → 创建（H5微应用或机器人）
3. 填写应用名称（如 `Hermes Agent`），描述可选
4. 创建后进入 **凭证与基础信息**，获取并保存：

| 凭证 | 说明 |
|---|---|
| **Client ID** (AppKey) | 钉钉应用标识 |
| **Client Secret** (AppSecret) | ⚠️ 仅显示一次，丢失需重新生成 |
| **App ID** | 钉钉应用 ID（如 `b98e17e6-c014-418f-ba00-85b72f16c05c`） |

### Step 2：添加机器人能力

1. 进入应用详情页 → **应用能力** → **机器人** → 开启
2. 配置机器人信息：

| 配置项 | 是否必填 | 要求 |
|---|---|---|
| 机器人名称 | 是 | 如 `Hermes` |
| 机器人图标 | 是 | 240×240px，png/jpeg/jpg |
| 机器人简介 | 是 | 最多 10 个字符 |
| 机器人描述 | 是 | 最多 200 个字符 |
| 消息预览图 | 是 | png/jpeg/jpg，不超过 2M |
| **消息接收模式** | 否 | **选择 Stream 模式**（推荐） |
| 消息接收地址 | 否 | Stream 模式无需填写 |

3. 点击 **发布（保存）** 机器人

> **Stream 模式优势**：无需公网 IP/域名/Webhook 服务器。WebSocket 从本机主动发起连接，NAT 和防火墙后均可工作。

### Step 3：发布应用

机器人发布后，必须在开发者后台 **发布应用** 才能生效。

### Step 4：获取钉钉用户 ID（可选）

1. 联系组织管理员，在 **钉钉管理后台 → 通讯录 → 成员** 查看
2. 或启动 Gateway 后给机器人发消息，从日志中获取 `sender_id`

## 二、Hermes Agent 配置

### Step 1：安装依赖

```bash
cd ~/.hermes/hermes-agent && python -c "import pm; pm.sync_venv(['dingtalk'], explicit=True)"
```

安装三个 Python 依赖包：

| 包名 | 用途 |
|---|---|
| `dingtalk-stream` | 钉钉 Stream 模式 WebSocket SDK |
| `httpx` | 异步 HTTP 客户端（发送回复） |
| `alibabacloud-dingtalk` | 钉钉 OpenAPI SDK（AI Cards、媒体下载） |

### Step 2：配置凭证

编辑 `$LOCALAPPDATA/hermes/.env`（Windows）或 `~/.hermes/.env`（Linux/macOS）：

```env
# 必填：钉钉应用凭证
DINGTALK_CLIENT_ID=dingiv66wzgg5sqsochw
DINGTALK_CLIENT_SECRET=***

# 安全设置
DINGTALK_ALLOWED_USERS=*              # 允许的用户（逗号分隔），* 表示所有
DINGTALK_ALLOW_ALL_USERS=true         # 允许所有用户（开发阶段方便调试）

# 可选：频道设置
DINGTALK_HOME_CHANNEL_NAME=default    # 主页频道名称
```

> **安全建议**：生产环境请设置 `DINGTALK_ALLOWED_USERS` 为具体用户 ID 列表，并关闭 `DINGTALK_ALLOW_ALL_USERS`。

### Step 3：启用平台（config.yaml）

确保 `config.yaml` 中钉钉平台已启用：

```yaml
platforms:
  dingtalk:
    enabled: true
```

### Step 4：可选行为配置

在 `config.yaml` 中调整行为：

```yaml
# 群聊中每个用户独立会话历史（默认 true）
group_sessions_per_user: true

gateway:
  platforms:
    dingtalk:
      extra:
        # 群聊必须 @mention 机器人才回复
        require_mention: true
        # 允许的用户列表（与 .env 中的 DINGTALK_ALLOWED_USERS 二选一）
        allowed_users:
          - user-id-1
          - user-id-2
        # 不需要 @的群聊列表
        free_response_chats:
          - cidABC==
          # 指定这些群内直接回复，无需 @mention
        # 自定义 @mention 唤醒词正则
        mention_patterns:
          - "^小马"
```

### Step 5：启动 Gateway

```bash
# 启动（前台）
hermes gateway

# 重启
hermes gateway restart

# 查看状态
hermes gateway status
```

启动后几秒钟内会建立 Stream 模式 WebSocket 连接。

## 三、验证与测试

### 检查连接状态

```bash
hermes gateway status
```

查看 Gateway 日志中的钉钉连接记录：

```bash
tail -50 ~/.hermes/logs/gateway.log | grep -i dingtalk
```

正常输出：
```
[Dingtalk] Robot SDK initialized (media download)
[Dingtalk] Connected via Stream Mode
✓ dingtalk connected
```

### 功能测试

1. **单聊测试**：在钉钉中直接给机器人发消息，应自动回复
2. **群聊测试**：在群内 `@机器人` 发送消息，应回复
3. **多用户测试**：不同用户在群内对话，会话历史应隔离

## 四、行为总览

| 场景 | 行为 |
|---|---|
| **单聊 (DM)** | 每条消息都回复，无需 @mention |
| **群聊** | 必须 `@机器人` 才回复（`require_mention: true` 时） |
| **多人共享群** | 每个用户独立会话，不共享上下文（`group_sessions_per_user: true` 时） |
| **指定群** | `free_response_chats` 中的群可免 @mention 直接回复 |

### 连接方式对比

| 特性 | Stream 模式 | HTTP 回调 |
|---|---|---|
| 公网地址 | ❌ 不需要 | ✅ 需要 |
| WebSocket | ✅ 长连接 | ❌ |
| 防火墙/NAT | ✅ 穿透 | ❌ |
| 推荐场景 | 本地部署、开发环境 | 云端部署 |

## 五、故障排查

### 1. 连接超时

```
✗ dingtalk disconnect timed out after 5.0s - forcing continue
```

- 检查 `.env` 中 `DINGTALK_CLIENT_ID` 和 `DINGTALK_CLIENT_SECRET` 是否正确
- 确认网络可访问 `https://api.dingtalk.com`
- 确认应用已发布

### 2. 发送消息失败

```
Access denied. One of the following scopes is required
```

- 在开发者后台检查应用权限是否开通
- 确认已发布应用版本

### 3. 群聊不回复

- 检查 `require_mention` 是否设为 `true`（需 @mention）
- 确认 `DINGTALK_ALLOWED_USERS` 是否包含当前用户
- 检查 `free_response_chats` 配置

### 4. 会话混乱

- 检查 `group_sessions_per_user` 是否设为 `true`
- 确认不同用户使用了正确的 User ID
